# W1 exit-gate demo — G-WAVE-1

**Who runs this:** a human (H-PO). Agents never run their own exit gate.
**Pass criterion (PLAN.md §7 W1):** the mock dashboard renders fixtures with **zero backend**.
**Expected time:** ~15 minutes. If any step fails, stop and file it in today's digest — ORCH turns failures into re-scoped packets.

## 0. Setup (2 min)

1. `git checkout main && git pull`
2. Install dependencies at the repo root (exact command is in the root README once W1-PLAT-2 lands the monorepo — see digest decision D3 on package manager).
3. Prove no backend is running: run `ps aux | grep -i kyndro` and check nothing platform-related is up. Keep this terminal visible for the rest of the demo.

## 1. Contract & fixtures (3 min)

4. Open `/contract/openapi.yaml`. Confirm these paths exist: auth, `/repos`, `/runs`, `/runs/:id`, `/runs/:id/obligations`, `/specs`.
5. Open `/contract/events/`. Confirm schemas for `run.started`, `run.updated`, `run.completed`.
6. Run the contract validation command documented in `/contract/README.md`. Expect zero errors.
7. Open `/fixtures/`. Confirm the golden set: one sample analyzed PR, obligations in all three verdict states, one counterexample, 10 candidate specs.

## 2. The core check — mock dashboard (5 min)

8. Start the mock server (command documented in `/app/mock/README.md`).
9. In `/app`, run the dev command (`npm run dev` or monorepo equivalent).
10. Open the printed localhost URL in your browser.
11. **Run list:** fixture runs render with status chips. Click through them.
12. **Run detail:** open a run. Obligations render in all three verdict states — VERIFIED (bounded), FALSIFIED, UNKNOWN — using the design-system chips.
13. **Counterexample:** click the FALSIFIED obligation. The counterexample fixture renders.
14. **Error states:** kill the mock server. Reload the page. Every screen shows a designed error state — never a blank page or raw stack trace.
15. **Recovery:** restart the mock server, reload, confirm the dashboard comes back.
16. Glance at the terminal from step 3: still nothing but the mock server and the dev server. Zero backend — that is the wave's whole point.

## 3. Design system (2 min)

17. Build and open the component workbench (command in `/app/design-system/README.md`).
18. Click through: typography, buttons, tables, the three verdict chips, monospace code block, diff viewer shell.
19. Confirm the a11y lint report is clean (command in the same README).

## 4. Landing page (2 min)

20. Build `/site` and open the local preview.
21. Submit a real email to the waitlist form → confirm it appears in the storage table.
22. Submit `not-an-email` → confirm a visible rejection.
23. Confirm the site is **not** publicly deployed. Publishing is your separate G-PUB decision.

## 5. Platform guardrails (1 min)

24. Open the most recent merged PR in GitHub. Confirm the four required checks ran: contract tests, full test suite, PR-size, territory.
25. In W1-PLAT-2's PR, confirm the seeded-violation tests passed (fake secret blocked; >400-line diff blocked; cross-territory diff blocked).

## Verdict

- **All green:** tick the W1 checkboxes in PLAN.md, then tell ORCH: **"open W2"**. That utterance is gate G-WAVE-1 passing — nothing else opens the next wave.
- **Anything red:** write what failed (step number + what you saw) into today's digest. Do not open W2.
